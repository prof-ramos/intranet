# drizzle

## Purpose

Drizzle ORM migration files and schema snapshots. Contains SQL migration files applied to PostgreSQL and the versioned snapshots used by Drizzle Kit for introspecting schema state. All migrations are zero-padded indexed SQL files tracked in a journal.

## Subdirectories

| Directory          | Purpose                                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------------------------- |
| `postgres/`        | SQL migrations, snapshots and manual non-transactional operations                                              |
| `postgres/meta/`   | Journal (`_journal.json`) and generated schema snapshots across migration milestones                           |
| `postgres/manual/` | SQL requiring an explicit runbook path, such as `CREATE INDEX CONCURRENTLY`; excluded from the normal migrator |

## Key Files

| File                              | Description                                                                         |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| `postgres/meta/_journal.json`     | Drizzle Kit journal tracking applied migration names, versions, and timestamps      |
| `postgres/meta/*_snapshot.json`   | Generated schema snapshots used by Drizzle Kit for state comparison                 |
| `postgres/snapshot-baseline.json` | Reconciled schema baseline used by migration tooling                                |
| `postgres/*.sql`                  | Canonical transactional migrations in `000N_description.sql` format                 |
| `postgres/manual/*.sql`           | Runbook-controlled, non-transactional SQL; never apply through `npm run db:migrate` |

## For AI Agents

### Working In This Directory

- SQL files follow the `000N_description.sql` naming pattern with zero-padded indices.
- Journal tracking is required in `meta/_journal.json`; generate migrations with the repository command instead of hand-editing snapshot metadata.
- Do not edit applied migrations; create a new file instead for schema changes.
- Snapshots are auto-generated by Drizzle Kit (`drizzle-kit generate`) and capture the full schema at a point in time.

### Testing Requirements

- Run `npm run test:db` to validate the live DB schema contract — validates tables, columns, enums, indexes, extensions, and migration alignment against `drizzle.__drizzle_migrations`.
- Run `npm run db:migrate` to apply pending migrations (guarded — checks journal before applying).
- Always validate the journal is consistent after any migration change.

### Common Patterns

- New schema changes start in `src/lib/db/schema/`, then use `npm run db:generate` to produce SQL, snapshots and journal changes.
- Production rollback follows `docs/runbook.md` and the relevant ADR; snapshots are not executable rollback scripts.
- Drizzle Kit config is in `drizzle.config.ts` at the project root.

## Dependencies

### Internal

- `../src/lib/db/schema/` — Drizzle TypeScript schema definitions
- `../src/lib/db/index.ts` — Database client with connection pool config

### External

- `drizzle-orm` — ORM runtime
- `drizzle-kit` — Migration tooling and snapshot generation
